# 损坏配置防崩溃与恢复提示设计

## 背景

应用启动时，`ProfileManager::load_or_default` 会解析应用数据目录中的 `state.json`，随后启动钩子生成快照并遍历 `profiles/*/meta.json`、读取活动 Codex 的 `auth.json`、`config.toml` 和 `codex-auth-switch.json` 标记。当前这些启动关键文件中的任意一次解析失败都可能向上传播并终止 Tauri 启动钩子，导致应用在窗口出现前退出。

本设计让应用在启动关键配置损坏时仍能启动，同时保留损坏数据、清楚告知用户影响和后续操作，并降低半写文件再次出现的概率。

## 目标

- 损坏的 `state.json`、任意 `profiles/*/meta.json`、`codex-auth-switch.json`，以及活动 Codex 的 `auth.json` 或 `config.toml` 不得导致应用启动失败。
- 自动隔离损坏的应用管理文件，并保留可供人工恢复的原始内容；Codex 自身配置只告警、不改写。
- 不删除档案目录中的 `auth.json`、`config.toml` 或其他文件。
- 启动后弹出一次恢复提示，列出损坏文件、备份位置、自动处理结果和用户需要执行的操作。
- 对已经隔离的同一批恢复事件只提示一次；未修复的 Codex 自身配置在当前进程中只提示一次，重启后继续提醒。
- 对应用管理的状态和元数据使用原子写入，降低进程中断造成文件截断的风险。

## 非目标

- 不从 `auth.json`、`config.toml` 猜测并自动重建完整 `meta.json`。
- 不尝试修复任意格式错误的 JSON 内容。
- 不改变 `auth.json` 或 `config.toml` 的现有校验和切换规则。
- 不把所有运行时读写错误都降级为静默忽略；与启动无关的明确操作仍应向用户返回错误。

## 恢复策略

### 损坏的 `state.json`

1. 成功读取但 JSON 反序列化失败时，将原文件移动到应用数据目录下带时间戳和唯一后缀的恢复文件，例如 `recovery/state.corrupt-20260710-120000-ab12cd34.json`。如果文件本身无法读取，则不移动原文件。
2. 使用 `StateFile::default()` 继续初始化，并通过原子写入生成新的有效 `state.json`。
3. 默认 Codex 目标目录会重新生效。恢复提示要求用户检查设置中的目标目录是否正确。
4. 如果隔离文件失败，应用仍使用内存中的默认状态继续启动，并在恢复提示中说明原文件未能移动及其原始路径。

### 损坏的 `meta.json`

1. 统一的档案枚举逻辑负责读取元数据，供档案列表、当前档案识别等启动链路复用。
2. 某个 `meta.json` 成功读取但反序列化失败时，将其移动到 `recovery/profiles/<profile-id>/meta.corrupt-<timestamp>-<suffix>.json`。如果文件本身无法读取，则不移动原文件。
3. 当前快照跳过该档案，继续加载其他有效档案。
4. 原档案目录及其中的 `auth.json`、`config.toml` 保持不变。恢复提示要求用户从恢复文件修复元数据，或重新导入该档案。
5. 如果隔离失败，仍跳过该档案并继续启动；恢复提示记录隔离失败和原始文件路径。

缺少 `meta.json` 的目录沿用现有行为：视为不完整档案并跳过，不新建恢复事件。

### 损坏的 `codex-auth-switch.json`

该文件是应用写入活动 Codex 目录的匹配标记，不包含认证正文。解析失败时，将其移动到应用恢复目录并忽略该标记；应用继续根据有效档案的内容哈希识别当前档案。后续成功切换配置时会自然生成新的标记文件。

### 无效的活动 Codex 配置

活动 Codex 目录中的 `auth.json` 和 `config.toml` 属于 Codex 运行配置。读取或解析失败时，应用不移动、不覆盖这些文件，也不尝试猜测修复内容。快照继续返回，当前档案和认证类型显示为未知，并在恢复提示中要求用户修复文件、从已有备份恢复，或重新切换一套有效档案。

## 恢复事件与提示生命周期

启动钩子可能早于前端首次调用 `load_snapshot` 发现并隔离损坏文件，因此恢复信息不能只保存在单次 `ProfileManager` 实例中。

后端维护独立的待确认恢复记录，保存于应用数据目录。每条记录包含：

- 事件标识；
- 配置种类（`state`、`profileMetadata`、`targetMarker`、`targetAuth` 或 `targetConfig`）；
- 原始文件路径；
- 恢复文件路径（隔离失败时为空）；
- 受影响的档案标识（适用时）；
- 自动处理结果；
- 用户建议操作；
- 发生时间。

写入恢复记录失败不能阻止应用启动。启动钩子会把当次发现的恢复事件放入 Tauri 管理的进程内待确认状态；成功持久化的记录则用于跨越启动钩子、前端加载阶段和异常退出。`load_snapshot` 合并进程内状态、持久化记录以及当前仍存在的无效活动 Codex 配置，并按事件标识去重。

已经隔离的应用管理文件不会再次产生事件。未被改写的无效活动 Codex 配置使用文件路径和内容指纹生成稳定事件标识；前端在当前进程中不会重复显示同一标识，但应用重启后会再次提醒，直至文件被修复。

`AppSnapshot` 增加待确认恢复事件列表。前端取得非空列表后显示一个合并弹框，并在用户点击任一完成按钮后调用确认命令。确认成功后删除待确认记录；确认失败时不影响应用继续使用，但下次启动仍会提示。

## 弹框交互

弹框标题为“检测到配置文件损坏”，内容分为三部分：

1. **发现的问题**：列出损坏文件或受影响的档案。
2. **已自动处理**：说明文件是否已隔离、有效档案仍可正常使用，以及恢复文件位置。
3. **你需要做什么**：

   - `state.json` 损坏时，检查当前 Codex 目标目录是否正确；
   - `meta.json` 损坏时，从恢复文件修复元数据或重新导入对应档案；
   - 活动 `auth.json` 或 `config.toml` 无效时，从备份恢复、手工修复，或切换到一套有效档案；
   - 隔离失败时，先备份原文件，再手工修复或移走损坏文件。

弹框提供两个按钮：

- `打开恢复目录`：打开应用数据目录下的恢复目录，然后确认本批提示。
- `我知道了`：关闭弹框并确认本批提示。

弹框不可通过点击遮罩静默关闭，避免用户未看到处置说明。多个损坏文件合并在同一个可滚动弹框中展示。

## 原子写入

应用管理的 `state.json`、`meta.json` 和待确认恢复记录采用同目录临时文件写入：

1. 将完整序列化内容写入唯一临时文件；
2. 刷新并关闭临时文件；
3. 用重命名替换目标文件；
4. 失败时清理临时文件并返回原始错误。

Windows 上替换已存在文件需要采用兼容的替换步骤，并确保失败时尽量保留旧文件。此辅助函数只用于本次涉及的应用管理 JSON，不扩展到 Codex 自身的 `auth.json` 或其他外部文件。

## 组件改动

### Rust 后端

- 为 `ProfileManager` 增加损坏状态恢复、宽容的活动配置识别和统一的宽容档案枚举逻辑。
- 增加恢复文件命名、隔离、待确认记录读写与确认能力。
- `snapshot` 返回有效档案和待确认恢复事件；当前档案识别复用同一档案枚举结果或同一宽容读取规则，无效活动配置降级为未知状态。
- 启动钩子通过 Tauri 管理状态保留当次恢复事件，确保持久化记录写入失败时前端仍能提示。
- 增加打开恢复目录和确认恢复提示的 Tauri 命令。
- 将本次涉及的应用管理 JSON 写入迁移到原子写入辅助函数。

### TypeScript 前端

- 扩展 `AppSnapshot` 类型，加入恢复事件列表。
- 新增专用配置恢复弹框渲染与交互，不复用只支持纯文本确认的删除确认框。
- 首次收到非空恢复事件列表时展示弹框，完成按钮调用对应后端命令。
- 弹框状态与普通通知条分离，避免刷新快照时被 `clearFlash` 清除。

## 错误处理原则

- JSON 内容损坏属于可恢复的数据问题：隔离、记录、跳过并继续启动。
- 应用数据目录本身无法创建或读取属于基础设施错误：保留现有错误返回，因为应用无法安全运行。
- 单个档案目录或元数据文件的读取失败不得影响其他档案展示。
- 隔离或恢复记录写入失败不得重新变成启动崩溃；界面至少展示当前进程能够收集到的错误详情。
- 用户主动打开某个已损坏档案时，仍返回明确错误，不伪造可编辑数据。

## 测试策略

### Rust 回归测试

- 损坏的 `state.json` 会被隔离，管理器使用默认状态成功载入，并生成恢复事件。
- 包含空字节的 `meta.json` 会被隔离，其他有效档案仍出现在快照中。
- 被隔离档案的 `auth.json`、`config.toml` 保持不变。
- 当前档案识别遇到损坏元数据时不会失败。
- 损坏的 `codex-auth-switch.json` 被隔离后仍可通过档案哈希识别当前档案。
- 活动 `auth.json` 或 `config.toml` 无效时快照仍可生成，文件内容保持不变，并产生稳定的待处理事件。
- 隔离完成后再次载入不会为同一文件创建第二份备份。
- 确认命令只清除已展示的恢复事件。
- 原子写入成功后目标 JSON 可解析，失败路径不会遗留被当作正式配置读取的临时文件。

### TypeScript 回归测试

- 快照包含恢复事件时显示“检测到配置文件损坏”弹框。
- 弹框列出已处理内容和对应的用户操作。
- `打开恢复目录` 调用打开目录与确认命令。
- `我知道了` 调用确认命令并关闭弹框。
- 空恢复事件列表不显示弹框，普通快照刷新不会重复显示已确认事件。

## 验收标准

- 使用截图场景中的全空字节 `meta.json` 启动时，应用窗口正常出现且其余档案可用。
- 用户看到包含损坏位置、恢复位置和下一步操作的弹框。
- 原始损坏内容可在恢复目录中找到；档案的认证和模型配置文件未被删除或改写。
- 确认弹框后，已经隔离的事件在刷新和重启时均不重复提示；仍未修复的 Codex 自身配置只在重启后再次提示。
- 完整 Rust 与 TypeScript 测试套件通过。
